# تصمیم‌ها

- رابط کاربری و راهنمای مالک فارسی خواهد بود؛ شناسه‌ها و کد انگلیسی می‌مانند.
- Node.js 24 و ESM انتخاب شدند تا با کانتینر تولید سازگار باشند و نیاز به مرحلهٔ build نباشد.
- برای توسعه از MariaDB 12.3 در Docker Compose و گذرواژهٔ ثابتِ صرفاً توسعه استفاده می‌شود؛ این گذرواژه برای تولید نیست.
- بارگذاری `.env.dev` با یک loader کوچک داخلی انجام می‌شود تا وابستگی dotenv اضافه نشود.
- وابستگی‌های تولید دقیقاً نسخه‌بندی شده‌اند و به فهرست مجاز brief محدودند: Express برای HTTP، mysql2 برای MariaDB، Busboy برای آپلود جریانی، Sharp برای پردازش تصویر، sanitize-html برای پاک‌سازی HTML و qrcode برای QR. نسخه‌های اولیهٔ mysql2، Sharp و sanitize-html با نسخه‌های امن‌تر جایگزین شدند؛ `npm audit --omit=dev` بدون آسیب‌پذیری گزارش می‌دهد.
- فونت‌های Vazirmatn Regular/Medium/Bold از دارایی‌های پروژهٔ محلی PnuCard کپی شدند تا بارگیری فونت به سرویس خارجی وابسته نباشد.
- مهاجرت 001 همهٔ جداول پایه را می‌سازد؛ ستون `news.cover_attachment_id` به‌دلیل رابطهٔ دوری خبر/پیوست FK ندارد و صحت آن در لایهٔ سرویس بررسی می‌شود.
- برای جلوگیری از ابهام مجوزی، دادهٔ MIT از `ahmadazizi/iran-cities` انتخاب شد؛ منبع GPL بررسی‌شده استفاده نشد. متن MIT همراه دادهٔ مشتق‌شده نگهداری می‌شود.
- مطابق نقش‌های مجاز در جدول سلسله‌مراتب، مدیر ارشد از نظر فنی می‌تواند مدیر شهر بسازد؛ رابط عادی مدیریت او همچنان می‌تواند روی مدیران استان متمرکز بماند.
- گذرواژهٔ موقت ایجاد/بازنشانی کاربر به‌صورت تصادفی ساخته و فقط یک‌بار در پاسخ همان درخواست برگردانده می‌شود؛ مقدار خام در دیتابیس یا گزارش ممیزی ذخیره نمی‌شود.
- برخلاف APIهای تغییردهندهٔ JSON، مسیر بارگذاری پیوست `multipart/form-data` می‌پذیرد؛ این استثنا برای ارسال جریانی فایل ضروری است و همچنان Origin هم‌مبدأ، نشست معتبر و سیاست دسترسی را الزامی می‌کند.
- API عمومی از cache درون‌فرایندی ۱۵ثانیه‌ای با ابطال رویدادی استفاده می‌کند؛ rate limit پیش‌فرض آن ۱۲۰ درخواست در دقیقه برای هر IP است. پاسخ اکنون‌پخش رادیو جداگانه ۲۰ ثانیه cache می‌شود و redirect سرور به URL دیگر را نمی‌پذیرد.
- چون نشان رسمی دانشگاه ارائه نشده، نشان و آیکن PWA از حرف «پ» با رنگ آبی به‌عنوان placeholder قابل جایگزینی استفاده می‌کنند.
- service worker پیکربندی عمومی و آخرین صفحهٔ خوراک را برای استفادهٔ آفلاین نگه می‌دارد و حداکثر ۸۰ تصویر اخیر را در cache تصویری حفظ می‌کند؛ push در این نسخه ساخته نمی‌شود.
- برای پخش رادیوی پیکربندی‌شده، CSP فقط در بخش `media-src` بارگذاری از HTTP(S) را مجاز می‌کند؛ اسکریپت، style و تصویر همچنان محدود به خود سایت (به‌علاوهٔ `data:` برای placeholder) هستند.
- برای رعایت بودجهٔ ۱۵۰ کیلوبایت، reader وزن‌های ۴۰۰ و ۵۰۰ را از فایل Regular مشترک می‌گیرد و فقط فایل Bold جداگانه بارگیری می‌شود؛ فایل Medium محلی نگه داشته شده تا در پنل مدیریتِ milestone بعدی استفاده شود.
- انتخاب‌گر شهر خواننده همهٔ ۳۱ استان را همیشه نشان می‌دهد؛ مرحلهٔ دوم فقط مراکز دانشگاهیی را فهرست می‌کند که مدیر فعال دارند (یا `visibility_override='show'`). برای استانی که هنوز هیچ شهرستان فعالی ندارد، پیام «فعلاً برای استان شما فعال نشده است.» نمایش داده می‌شود. ذخیرهٔ انتخاب همچنان همیشه شناسهٔ شهر است.
- شاخهٔ `deploy` دیگر با force-push بازنویسی نمی‌شود: هر بار یک commit ادغامی با والدین `origin/deploy` و `main` ساخته می‌شود که درخت آن برابر `main` به‌علاوهٔ `node_modules` لینوکسی است. در نتیجه روی سرور `git pull --ff-only` کار می‌کند.
- نام فایل‌های CSS/JS نسخه‌دار (`*.v2.*`) و کش service worker (`pnunews-shell-v2`) با هر تغییر ظاهری باید همراه هم افزایش یابند، وگرنه بازدیدکنندگان قبلی نسخهٔ قدیمی را می‌بینند (این فایل‌ها یک‌ساله و immutable کش می‌شوند).
- اصلاح املای نام مناطق با migration `002_fix_region_names.sql` (بر اساس `code` پایدار) انجام می‌شود تا نیازی به اجرای دستی seed روی سرور نباشد.
- مدیریت دسته‌بندی‌ها مثل مدیریت مناطق فقط برای مدیر ارشد است (`canManageRegion`)؛ فهرست دسته‌بندی‌ها برای انتخاب در ویرایشگر خبر برای همهٔ مدیران خوانا است.
- آپلود پیوست‌ها فایل‌به‌فایل (هر فایل یک درخواست) انجام می‌شود تا پیشرفت هر فایل نمایش داده شود و خطای یک فایل بقیه را متوقف نکند؛ سقف‌های سمت سرور (۱۰ تصویر، ۸ فایل، ۱۲/۱۵ مگابایت) دست‌نخورده‌اند.
- خبرهای واردشده خودکار از پورتال (دارای `source_url`) را ربات سیستمی با نقش مدیر ارشد ثبت می‌کند و طبق قاعدهٔ «بالادستی دیده نمی‌شود» برای مدیران استان و مرکز و روابط عمومی مرکزی پنهان است؛ فقط مدیر ارشد آن‌ها را می‌بیند و حذف می‌کند.
- در رایانهٔ رومیزی (عرض ۹۶۰ پیکسل به بالا) کارت‌های صفحهٔ خبر به‌صورت ماسونری چیده می‌شوند: شبکهٔ ۸ پیکسلی که هر کارت به اندازهٔ ارتفاع خودش ردیف می‌گیرد (`layoutMasonry` در reader). موبایل و تبلت همان شبکهٔ قبلی است.
