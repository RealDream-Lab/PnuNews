آخرین بررسی: ۲۰۲۶-۱۰-۲۶

- [x] **M0 — اسکلت و محیط توسعه:** فایل‌های پیکربندی و راهنما موجودند؛ سرویس MariaDB توسعه در حال اجراست و migrationها با موفقیت بررسی/اعمال شدند.

## Step 0 — پیش‌پرواز و smoke test محلی (انجام‌شده)

- `PROMPT.md` در `.gitignore` است و tracked نیست؛ بررسی الگوهای secret در README و اسناد، موردی نیافت. مسیرها و نام containerهای عملیاتی در `docs/OPERATIONS.md` برای runbook لازم‌اند و credentialی در آن دیده نشد.
- `npm test`: ۳۷ تست موفق، ۰ شکست.
- smoke test API با دیتابیس توسعه انجام شد: ساخت super-admin از CLI، ورود و ثبت TOTP، ورود با TOTP، ساخت مدیر استان و شهرستان، رد مدیر دوم فعال همان شهرستان با HTTP 409، انتشار خبر استانی همراه تصویر JPEG پردازش‌شده به WebP و PDF، بررسی feed/detail و snapshot ناشر، دانلود فایل، و روشن/خاموش‌کردن تنظیم رادیو.
- smoke test تعاملی در Chrome headless انجام شد: انتخاب استان و سپس شهرستان از picker، نمایش خبر در feed، تغییر تم به light و dark، ورود super-admin، ثبت TOTP و نمایش backup codes، رفتن به تنظیمات، و روشن/خاموش‌کردن رادیو و بررسی player در خواننده. این آزمون DOM/تعامل مرورگر بود و ارزیابی ظاهری دستی محسوب نمی‌شود.
- Safari 27.0.1 در این Mac تأیید نشد: با وجود فعال‌شدن `Allow Remote Automation`، `safaridriver --enable` دو بار با `EXC_BAD_ACCESS`/`SIGSEGV` در `authorizationWithUser:password:` کرش کرد و ساخت WebDriver session نیز موفق نشد. این محدودیت ابزار سیستم است؛ هیچ نتیجه‌ای از این آزمون به‌عنوان تأیید Safari گزارش نمی‌شود.
- در smoke test باگ CLI یافت و اصلاح شد: `scripts/create-super-admin.js` پس از خواندن secret ورودی stdin را pause نمی‌کرد و فرایند پس از ساخت مدیر باز می‌ماند.
- پس از smoke test، حساب‌ها و خبر موقت صفر بودند، تنظیم radio قبلی (`radio_enabled=0`) برگشت، فایل‌های موقت پاک شدند و `uploads/` خالی بود.
- دامنهٔ نهایی `PUBLIC_URL` هنوز از مالک دریافت نشده است؛ در Step 7 پرسیده می‌شود.
- push/deploy، تنظیم سرور و restart تولید انجام نشده‌اند و در این مرحله انجام نمی‌شوند.
- CSP عمداً HTTPS media را برای رادیوی قابل‌تنظیم مجاز می‌کند؛ محدودیت host در نظر گرفته نشده است.

## Step 1 — PUSH (انجام‌شده)

- مخزن GitHub عمومی است (`PUBLIC`). آزمون `ssh -T` موفق بود: احراز هویت با حساب `RealDream-Lab`.
- شاخهٔ `main` با push عادی و بدون force منتشر شد؛ آخرین تغییر کد در commit `f6ee01d` است.
- اجرای نخست `scripts/make-deploy-branch.sh --prepare-only` نشان داد checker نام قدیمی `sharp-linux-x64.node` را می‌خواست، در حالی‌که sharp 0.35.5 باینری نسخه‌دار `sharp-linux-x64-0.35.5.node` دارد. checker اصلاح شد و regression test اضافه شد؛ commit `f6ee01d` — «اصلاح تشخیص باینری لینوکسی sharp».
- `npm test`: ۳۸ تست موفق، ۰ شکست؛ regression test checker و `bash -n scripts/make-deploy-branch.sh` هم موفق شدند.
- `deploy` با `scripts/make-deploy-branch.sh --prepare-only` ساخته و سپس push شد. باینری sharp و libvips در شاخه از نوع ELF x86-64 هستند؛ ۲۱۳۰ فایل `node_modules/` در آن قرار دارد و بررسی مسیرهای ممنوع (`.autostart`, `.env` واقعی, `uploads/`, `PROMPT.md`) موردی نیافت.
- push اولیه به‌علت سرعت SSH کند قطع شد؛ retry با SSH keepalive موفق شد. `main` هیچ‌گاه force-push نشده است.
- گزارش Step 1 روی `main` ثبت و push شد؛ همان وضعیت مستندات نیز به `deploy` منتقل و push شد و هر دو ref در GitHub تأیید شدند.

## Step 2 — SERVER GIT SETUP (انجام‌شده)

- روی سرور، مسیر موجود `/opt/docker/nodejs/workspace/PnuNews` به مخزن GitHub متصل شد؛ `origin` همان SSH URL مورد انتظار بود و fetch هر دو شاخهٔ `main` و `deploy` موفق شد.
- شاخهٔ محلی `deploy` از `origin/deploy` ساخته و tracking شد. `git status --short --branch` پاک است.
- پوشهٔ موجود `uploads/` پس از checkout تأیید شد و حفظ شده است. مخزن عمومی است؛ Deploy key لازم نبود.

## Step 3 — SERVER CONFIG (انجام‌شده)

- روی سرور `.autostart` از `.autostart.example` ساخته شد؛ مجوز فایل `600` است.
- فقط به‌صورت امن بررسی شد که `APP_SECRET` یک مقدار ۶۴ رقمی hex معتبر است، `DB_PASSWORD` دیگر placeholder نیست و `PUBLIC_URL` تنظیم شده است؛ هیچ secretی در گزارش یا مخزن ثبت نشده.
- `PUBLIC_URL` فعلی طبق اعلام مالک موقت است؛ دامنهٔ نهایی در Step 7 تأیید و پیش از ورود واقعی اعمال می‌شود.

## Step 4 — SERVER DATABASE (انجام‌شده)

- در container `mariadb` پایگاه دادهٔ `pnu_news` با `utf8mb4` ساخته شد؛ کاربر اختصاصی `pnu_news`@`%` ساخته و دسترسی لازم به schema اعطا شد.
- اتصال با همان کاربر تأیید شد؛ query نتیجهٔ `DATABASE() = pnu_news` و `CURRENT_USER() = pnu_news@%` داد. هیچ گذرواژه‌ای در گزارش ثبت نشده است.

## Step 5 — SERVER MIGRATE / SEED / ADMIN (انجام‌شده)

- environment container `nodejs` در ابتدا متغیرهای لازم پروژه را نداشت؛ برای هر فرمان `.autostart` فقط در همان process با `bash` source شد و container پیش از زمان مقرر restart نشد.
- `migrate.js` موفق شد و `001_core.sql` را اعمال کرد؛ `seed.js` موفق شد؛ super-admin به‌صورت تعاملی ساخته شد و پیام الزام ثبت 2FA در نخستین ورود نمایش داده شد.
- هیچ username، گذرواژه یا secretی در این گزارش ثبت نشده است.

## Step 6 — FIRST ACTIVATION (انجام‌شده)

- container `nodejs` روی سرور restart شد؛ این کار مطابق هشدار عملیاتی، PnuCard را هم موقتاً restart می‌کند.
- logهای startup نشان دادند PnuNews روی پورت `3010` گوش می‌دهد و خطای واضحی در خروجی محدودشده نبود.
- بررسی داخلی `/healthz` نتیجهٔ `HTTP_STATUS=200`, `BODY=ok` داد؛ مالک هم بازشدن سایت روی دامنهٔ موقت را گزارش کرد.
- picker عمومی فعلاً شهر/استانی نشان نمی‌دهد؛ این با policy فعلی سازگار است چون فقط super-admin ساخته شده و شهرهای `auto` بدون مدیر شهرستان فعال در API عمومی دیده نمی‌شوند. این وضعیت پس از provisioning مدیران در مرحلهٔ ورود واقعی دوباره بررسی می‌شود.

## Step 7–8 — گزارش مالک / دامنهٔ اصلی معوق

- مالک گزارش کرده تنظیم Nginx Proxy Manager و مراحل ورود اولیهٔ Step 8 را خودش انجام داده است؛ این بخش‌ها در این نشست مستقلاً بررسی نشدند.
- فعال‌سازی دامنهٔ اصلی به چند روز بعد موکول شده است. `PUBLIC_URL` فعلی موقت تلقی می‌شود؛ پس از تعیین دامنه، proxy/TLS، مقدار `PUBLIC_URL` و restart نهایی باید دوباره با هم تأیید شوند.

## Step 9 — RESTART SCRIPT (آزموده شد)

- `scripts/restart.sh` روی سرور موفق شد و گزارش کرد PnuNews متوقف و توسط `start-all.sh` دوباره اجرا می‌شود.
- قبل/بعد، container `nodejs` با `RESTARTS=0` و همان `StartedAt` باقی ماند؛ PID مربوط به PnuCard ثابت (`15`) و PID مربوط به PnuNews از `16` به `97` تغییر کرد. بنابراین PnuCard restart نشد.
- health داخلی پس از restart همچنان `HTTP_STATUS=200`, `BODY=ok` بود. فیلتر محدود log در بازهٔ پایانی خطی برنگرداند؛ تأیید عدم restart PnuCard بر پایهٔ PID و وضعیت container است.

## بازبینی ظاهر و انتخاب‌گر (۲۰۲۶-۱۰-۲۶، پس از استقرار)

- بررسی با Chrome واقعی نشان داد: picker روی سایت زنده خالی بود (شهرها فقط با مدیر فعال نمایش داده می‌شدند)، هدر روی عرض ۳۸۱ تا ~۴۳۰px سرریز می‌کرد، ردیف‌های picker با نتیجهٔ کم کش می‌آمدند، جست‌وجو «آ/ا» را یکی نمی‌گرفت، و نام ۴۲ منطقه املای نادرست داشت.
- اصلاح‌ها: نمایش همهٔ استان‌ها + پیام «فعلاً برای استان شما فعال نشده است.»، جست‌وجوی سراسری شهر در مرحلهٔ اول، هدر تک‌ردیفی و بدون سرریز، بازطراحی فید (حذف hero، کارت با ارتفاع خودکار، کارت بدون تصویر، کارت شاخص دسکتاپ، حذف تکرار خبر مهم)، رفع ایرادهای ظاهری ورود/کاربران پنل مدیریت، و افزایش نسخهٔ asset‌ها به v2.
- migration ۰۰۲ املای نام مناطق را اصلاح می‌کند؛ `scripts/migrate.js` فایل‌های نقطه‌دار (مثل `._*` روی دیسک‌های exFAT) را نادیده می‌گیرد.
- هنوز انجام نشده: درخت کاربران جمع‌شدنی با جست‌وجو، تعویض input فایل بومی مرورگر در پنل موبایل، آیکن SVG برای تب‌های موبایل، و تطبیق فهرست شهرستان‌ها (منبع ۲۰۲۰) با تقسیمات فعلی.

## بازطراحی ویرایشگر خبر و مقصد انتشار

- مقصد انتشار بر اساس نقش: مدیر ارشد «کل کشور» یا «استان‌های مشخص» (انتخاب چندتایی با جست‌وجو، انتخاب همه و پاک کردن)؛ مدیر استان «کل استان» یا «شهرستان‌های مشخص»؛ برای مدیر شهرستان کادر مقصد اصلاً نمایش داده نمی‌شود و خبر همیشه برای شهرستان خودش ثبت می‌شود. همین انتخاب‌گر در انتشار سریع موبایل هم استفاده می‌شود.
- ویرایشگر دسکتاپ دو ستونه شد: متن در ستون اصلی، و در کنار آن کارت انتشار (وضعیت، مقصد، دسته‌بندی، «اکنون/زمان‌بندی»، یک دکمهٔ اصلی انتشار و یک دکمهٔ ذخیره). گزینه‌های کم‌کاربرد (خبر مهم/فوری، انقضا، لغو انتشار، حذف) در «گزینه‌های بیشتر» و رسانه/پیوست‌ها در بخش جمع‌شونده قرار گرفتند. برای خبر منتشرشده فقط «ذخیرهٔ تغییرات» نشان داده می‌شود.
- فایل‌های پنل به `admin.v3.js` و `styles.v3.css` تغییر نام یافتند تا کش مرورگر قدیمی نشود.

- جملهٔ «در کنار خبرهای کشوری» و دکمه‌های همه/کشوری/استان/شهر موقتاً حذف شدند؛ محدوده همیشه «همه» است و قرار است بعداً در تنظیمات بیاید.
- PWA: مانیفیست با آیکون‌های PNG (any و maskable، ۱۹۲ و ۵۱۲)، آیکون iOS و فاوآیکون از روی لوگوی پیام نور؛ سرویس‌ورکر در رویداد `load` ثبت می‌شود و پیشنهاد نصب (بنر داخل داک، ۳ ثانیه پس از `beforeinstallprompt`؛ در iOS (همهٔ مرورگرها) راهنمای «افزودن به صفحهٔ اصلی») با بستنِ کاربر ۱۴ روز پنهان می‌ماند؛ افزودن `?install=1` به آدرس برای تست آن را دوباره نشان می‌دهد.
- اصطلاح «شهرستان» در تمام متن‌های رابط کاربری (خواننده، پنل مدیریت، پیام‌های API و مانیفیست) با «مرکز دانشگاهی» جایگزین شد؛ نام‌های فنی (`city`، `city_admin`) و مستندات تاریخی تغییر نکردند.
- تمام‌صفحه فقط برای دستگاه‌های لمسی: `manifest-mobile.webmanifest` (با `display_override: [fullscreen, standalone]`) را `manifest-switch.v1.js` فقط وقتی `pointer: coarse` و `hover: none` باشد جایگزین می‌کند؛ دسکتاپ همان مانیفیست `standalone` را می‌گیرد. در Android نوار وضعیت و ناوبری پنهان می‌شود؛ در iOS نوار وضعیت `black-translucent` است و یک نوار آبی هم‌اندازهٔ safe-area بالای صفحه می‌نشیند تا آیکون‌های سفید خوانا بمانند.
- اعلان به‌روزرسانی: سرویس‌ورکر جدید دیگر خودکار فعال نمی‌شود (`skipWaiting` حذف شد)؛ خواننده بنر «نسخهٔ جدید آماده است» نشان می‌دهد، با «به‌روزرسانی» پیام `SKIP_WAITING` می‌فرستد و صفحه پس از `controllerchange` دوباره بارگذاری می‌شود. هر ساعت و هنگام بازگشت به برنامه وجود نسخهٔ جدید بررسی می‌شود. اعلان فقط وقتی می‌آید که فایل `sw.js` تغییر کرده باشد، پس در هر انتشار `CACHE_NAME` و فهرست asset‌ها باید همراه نسخهٔ فایل‌ها بالا برود.
- شمارهٔ نسخه در فوتر («نسخه ۰.۱.۱») از نام فایل `app.v0.1.1.js` که واقعاً در حال اجراست خوانده می‌شود و با `package.json` یکی است؛ تست `html-shell` هماهنگی نام asset‌ها، کش سرویس‌ورکر و `package.json` را می‌سنجد.
- رفع باگ بنر به‌روزرسانی: اگر نسخهٔ سومی در حالی که بنر نسخهٔ قبل باز بود منتشر می‌شد، دکمه به worker منسوخ پیام می‌داد، صفحه با تایمر دوباره بارگذاری می‌شد و بنر دوباره می‌آمد؛ حالا همیشه `registration.waiting` فعلی فعال می‌شود.
- نسخه‌گذاری معنایی: از این پس نسخه `major.minor.patch` است (فعلاً ۰.۱.۱؛ تا انتشار قابل‌عرضه زیر ۱.۰.۰ می‌ماند). برای بالا بردن نسخه فقط `npm run bump -- 0.1.2` را بزنید؛ این دستور `package.json` و `package-lock.json`، نام فایل‌های asset در `public/`، همهٔ ارجاع‌ها و نام کش سرویس‌ورکر را با هم عوض می‌کند. هر تغییر در فایل‌های asset یا `sw.js` باید با bump همراه باشد، چون این فایل‌ها یک سال کش می‌شوند و بنر به‌روزرسانی هم از تغییر `sw.js` می‌آید. شماره‌های قدیمی v2 تا v11 فقط شمارندهٔ داخلی کش بودند و با ۰.۱.۱ جایگزین شدند.
- صدای پیش‌فرض رادیو ۶۰٪ است (انتخاب قبلی کاربر حفظ می‌شود)؛ برچسب محدوده: شهر خود کاربر بدون برچسب، کشوری «سازمان مرکزی»، استانی «دانشگاه پیام نور استان …»؛ متای روی عکس حداکثر دو خط است.
- نسخهٔ asset‌ها: `styles.v0.1.1.css`، `app.v0.1.1.js`، `theme.v0.1.1.js`، `admin.v0.1.1.js`، `styles.v0.1.1.css` و کش SW به `pnunews-shell-v0.1.1`.
- نسخهٔ ۰.۱.۷: بنرهای «نصب برنامه» و «نسخهٔ جدید آماده است» دیگر به داک چسبیده نیستند؛ کارت شناور بالای فوتر می‌نشینند (ارتفاع داک با `ResizeObserver` در `--dock-height` نگه داشته می‌شود تا با نوار رادیو در موبایل هم روی آن نیفتند).
- فوتر (نام، شمارهٔ نسخه و نوار رادیو) در ماژول مشترک `public/shared/dock.v0.1.7.js` است و هم خواننده و هم پنل مدیریت از آن استفاده می‌کنند؛ در پنل مدیریت فوتر انتهای صفحه است (چسبنده نیست) و پس از ذخیرهٔ تنظیمات رادیو تازه می‌شود.
- همهٔ لیست‌های کشویی پنل مدیریت (`select`) یک ظاهر دارند: بدون فلش پیش‌فرض مرورگر و با همان شورون سایر بخش‌های بازشونده (نسخهٔ روشن و تیره).
- بخش تازهٔ «دسته‌بندی‌ها» (فقط مدیر ارشد): افزودن، تغییر نام، فعال/غیرفعال، جابه‌جایی ترتیب و حذف. حذف دسته‌بندی خبرها را پاک نمی‌کند، فقط «بدون دسته‌بندی» می‌شوند. دسته‌بندیِ غیرفعال برای خبرِ تازه انتخاب نمی‌شود ولی روی خبرهای قبلی می‌ماند و ذخیرهٔ دوبارهٔ آن خبر خطا نمی‌دهد. API: `GET/POST /api/admin/categories`، `POST /api/admin/categories/reorder`، `PATCH/DELETE /api/admin/categories/:id`؛ رویدادها در گزارش ممیزی با موجودیت `category` ثبت می‌شوند.
- پیوست‌های ویرایشگر خبر: سه ناحیهٔ کشیدن‌ورهاکردن (جلد، تصاویر دیگر، فایل‌ها) به‌جای دکمهٔ انتخاب فایل؛ کلیک برای انتخاب هم کار می‌کند. هر فایل جداگانه با `XMLHttpRequest` ارسال می‌شود تا نوار پیشرفت خودش و نوار کلی داشته باشد؛ فایل ناموفق در فهرست می‌ماند و با ذخیرهٔ دوباره دوباره تلاش می‌شود. پیش‌نمایش تصویر با `data:` ساخته می‌شود چون CSP نشانی `blob:` را نمی‌پذیرد.

- نسخهٔ ۰.۱.۲۲: رفع باگ آیکون دکمهٔ رادیو؛ پس از «توقف» آیکون به «پخش» برنمی‌گشت، چون `stop()` بلافاصله پس از `pause()` متد `load()` را صدا می‌زند و `load()` رویداد `pause` در صف را دور می‌ریزد. حالا آیکون و برچسب دکمه مستقیماً در `stop()` (تابع `setPlayingUi`) تنظیم می‌شود؛ خطای پخش یا ناموفق‌بودن `play()` هم دکمه را به «پخش» برمی‌گرداند. تست‌های موجود (`test/`) بخش واقعی مجموعهٔ تست پروژه‌اند و نگه داشته شدند.
- نسخهٔ ۰.۱.۲۳: منوی «مدیریت کاربران» برای مدیر مرکز دانشگاهی (`city_admin`) نمایش داده نمی‌شود، چون پایین‌ترین سطح است و کاربر زیرمجموعه ندارد (ورود مستقیم به آن صفحه هم به داشبورد برمی‌گردد). موارد نوار پایین موبایل که در نوار کناری دسکتاپ نبودند اضافه شدند: «خوراک خبر» و «حساب کاربری»؛ «خبر سریع» و «خبرهای من» در دسکتاپ با ویرایشگر کامل و فیلتر «خبرهای من» در «مدیریت خبرها» پوشش داده می‌شوند. بخش «حساب کاربری» (برای همهٔ نقش‌ها، دسکتاپ و موبایل) فرم «تغییر گذرواژه» دارد (گذرواژهٔ فعلی، تازه و تکرار آن)؛ پس از تغییر، سرور همهٔ نشست‌ها را می‌بندد و کاربر به صفحهٔ ورود می‌رود.

## گام بعدی

- برای cutover نهایی، پس از مشخص‌شدن دامنهٔ اصلی، `PUBLIC_URL` و Nginx Proxy Manager را هماهنگ و restart نهایی/health و ورود HTTPS را تأیید کنید. روند update و دستورات backup در `docs/OPERATIONS.md` ثبت شده‌اند.
